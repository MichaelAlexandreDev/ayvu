Scope: Arch Linux x86_64, GNOME Wayland with XWayland. Linux as the first
product target is a proposal, not a supported-platform claim. No Windows or
macOS runtime was tested. Raw observations are in
[comparison-host-2026-10-06.json](comparison-host-2026-10-06.json).

## Startup and packaging

Startup samples ran sequentially, after the builds finished, using the same
runner and seven fresh processes each. Cold application startup in this
protocol means a new process and fresh home/config/cache directories, not an
OS cache reset. Readiness means the first callback
after showing the window. OS page-cache state was not reset; these values do
not establish controlled cold-cache startup or confirmed compositor display.

Both packages used PyInstaller 6.22.3 and hooks 2026.8. The standalone smoke
launches removed Python, loader, Tcl/Tk and Qt plugin-path overrides; both
emitted `AYVU_SPIKE_READY`, exited 0 and produced empty stderr. This checks
startup, not a distributable Ayvu product, an installer or a different Linux
distribution. The artifacts stayed in the temporary build root.

## Keyboard, focus and scaling

The [native-widget probe](../probe_widgets.py) delivers toolkit events to live
widgets. It is automated evidence, not a physical-keyboard session. The Qt
probe pumps events while releasing the Python GIL so its QThread can execute.

Qt initially failed the focus-transition observations. The disposable window
now explicitly focuses Cancel after starting and Start after finishing. After
that correction, all eleven keyboard/state checks passed at effective Qt
device-pixel ratios 1.0, 1.25, 1.5 and 2.0. Checks cover Tab/Shift+Tab skipping
disabled Cancel, Space start/cancel/restart, Enter start, progress, completion
and focus restoration. Disabled actions cannot be reached with Tab.

The native XWayland Qt ratio was 2.0, so the probe divided the requested scale
by that baseline and recorded the resulting ratio. It did not change GNOME
monitor settings. Native Tk scaling used `(96 / 72) × factor`; the raw report
records the actual Tcl value rather than assuming it equals the request.

Qt snapshots have readable labels and controls within the window at
[100%](qt-scale-1.png), [125%](qt-scale-1.25.png),
[150%](qt-scale-1.5.png) and [200%](qt-scale-2.png). These are synthetic widget
captures, not proof of monitor-switch behavior or human focus usability.

Tk Space start/cancel/restart/completion worked at all four factors. Enter did
not start the task, and button rectangles exceeded the fixed-height window.
The probe explicitly focused Cancel for the Tk action sequence; it does not
claim automatic focus restoration. Font-width observations are diagnostic
estimates, not a visual-layout assessment. An attempted Tk window capture was
black and was excluded from published evidence. These results concern this
Tk 8.6 prototype; they do not prove that a revised Tk layout cannot work.

## Accessibility

The corrected Qt/Accerciser launcher passed live AT-SPI checks after the focus
change: API properties, button actions, progress, cancellation, restart and
100% completion. Qt role/name/value observations and the optional bus-address
workaround are detailed in
[the accessibility record](accessibility-host-2026-10-06.md).

A separately launched Tk 8.6 window remained alive during ten AT-SPI registry
polls spaced 0.4 seconds apart. Its uniquely named application did not appear.
This is concrete negative evidence on this host, not a screen-reader test on
other OSes or on Tk 9.1. No user books, translation service or audio were used.

## Remaining human and platform checks

- Physical keyboard operation, spoken announcements and their timing, and
  visible-focus usability have no human result yet.
- Actual monitor scale changes and multi-monitor movement remain untested.
- The maintainer must approve Linux-first evaluation scope or provide the
  additional Windows/macOS evidence required for a broader target.
- Bundles lack distribution notices; see the
  [packaging review](packaging-review-2026-10-06.md).

The ADR remains Proposed. These observations support a reviewable research
contribution, but do not satisfy every required check for closing issue #124.
Controlled OS cold-cache startup is an additional unmeasured performance
scenario; the reported protocol does not claim that coverage.

## Repository validation

`uv run --offline --locked pytest tests spikes/desktop-stack/test_spike_tools.py`
passed all 438 tests, with no skips. This includes the CLI/core regression
suite, research-tool checks and local document-link validation. Native GUI and
AT-SPI observations above ran separately against their real toolkit/session
boundaries; the ordinary Python suite is not presented as GUI evidence.
